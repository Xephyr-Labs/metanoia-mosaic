# Rich responses: tables, charts, diagrams, math, SVG, images, choices

Date: 2026-10-10. Branch: `rich-responses` (based on `review-hardening`).

## Goal

Assistant replies in the widget render like a modern chat app: GFM tables, plots, Mermaid diagrams, KaTeX math, model-written SVG illustrations, inline images, and clickable choice buttons. Model output is still never parsed as HTML. The widget core stays dependency-free; heavy libraries load only when a reply needs them.

Scope: `@metanoia/widget` (and the React wrapper, which inherits it) plus a prompt addition in `@metanoia/core`. Out of scope: headless client and React Native rendering, chart types beyond the five below, zoom/pan, sandboxed iframe HTML.

## 1. Module layout

`renderMarkdown` and `inline` move out of `packages/widget/src/index.ts` into `packages/widget/src/render/`:

- `markdown.ts` — block/inline parser. Existing subset plus GFM tables, blockquotes, `---` rules, `~~strike~~`, task lists (`- [ ]` / `- [x]`, read-only), `![alt](url)` images, `$…$` / `$$…$$` math spans.
- `blocks.ts` — fenced-block dispatch by language tag: `chart`, `choices`, `mermaid`, `svg`, `math`. Any other tag renders as `<pre><code>` with a language label and a copy button.
- `chart.ts` — hand-rolled SVG charts.
- `lazy.ts` — cached dynamic `import()` loader (one promise per URL) for Mermaid and KaTeX.

`index.ts` calls `renderMarkdown(host, text, ctx)` where `ctx` carries options, labels, theme, `send(text)`, `streaming` and `interactive` flags.

## 2. Block behavior

**Tables.** `<table>` inside a horizontally scrolling wrapper; first row is `<thead>`; `:---`, `:---:`, `---:` set column alignment; inline Markdown in cells. A row with a different cell count is padded or truncated to the header width.

**Charts.** Fenced ` ```chart ` JSON:

```json
{"type":"bar","title":"Revenue","labels":["Q1","Q2"],"series":[{"name":"2026","data":[4,6]}],"unit":"$k"}
```

`type` is one of `bar | line | area | pie | scatter`. For `scatter`, `data` is `[x,y]` pairs and `labels` is optional. Rendering: SVG with `viewBox`, responsive width, y-axis with ~5 nice ticks, x labels (thinned when crowded), legend when more than one series, `<title>` on every mark for hover tooltips, colors from the fixed categorical palette (see Limits). Accessibility: `role="img"` with `aria-label` from `title`, plus a visually hidden `<table>` of the data. Limits: 8 series (and 8 pie slices), 500 points per series. Series colors use the dataviz skill's validated 8-slot categorical palette, with separate light and dark steps, assigned in fixed order. Invalid JSON or schema → code block with a "Couldn't render chart" note.

**Choices.** Fenced ` ```choices ` JSON:

```json
{"question":"Which plan?","options":["Starter",{"label":"Pro (annual)","value":"I'd like the Pro annual plan"}],"multi":false}
```

Rendered as a button group under the reply. Single-select: clicking sends `value ?? label` as the next user message. `multi:true`: toggle buttons (`aria-pressed`) plus a Send button that sends the selected labels joined with ", ". Only choices in the latest assistant message are interactive; sending any message (typed or chosen) disables all earlier choice groups, and the chosen option keeps a selected style. Choices loaded from History render disabled. Limits: 12 options, 80 chars per label.

**Mermaid.** Lazy-loads Mermaid ESM, `initialize({startOnLoad:false, securityLevel:"strict", theme})`, `render()` to an SVG string, displayed as `<img src="data:image/svg+xml;…">` with `alt` from the source's first line. Never inserted into the DOM as markup.

**SVG.** ` ```svg ` content is displayed only as `<img src="data:image/svg+xml;charset=utf-8,…">`. Image-mode SVG cannot run scripts or fetch external resources, which removes the XSS surface without a sanitizer. Content over 100 KB or not starting with `<svg` renders as code.

**Math.** `$…$` inline, `$$…$$` and ` ```math ` display. Lazy-loads KaTeX with `trust:false, throwOnError:false, output:"mathml"`; the browser renders MathML natively, so no KaTeX CSS or fonts are loaded (fonts declared inside a shadow root do not apply). KaTeX's markup is generated by KaTeX from the TeX source, not by the model, and is the one place the widget inserts library-generated markup. Inline `$` requires non-space after the opening and before the closing delimiter, and no digit right after the closing delimiter, so prices like "$5 and $10" stay text. Until KaTeX loads, the TeX source shows in a `code` element.

**Images.** `![alt](url)` with `http:`, `https:` or `data:image/(png|jpeg|gif|webp)` only. `loading="lazy"`, `referrerpolicy="no-referrer"`, max-width 100%. Click opens the image in a new tab (http/https only). On error, replaced by the alt text.

## 3. Streaming

The reply re-renders on every delta, as today. An unclosed fenced block of a rich type shows a "Rendering…" placeholder instead of partial JSON; unclosed plain code renders as code. Lazy-rendered results (Mermaid, KaTeX) are cached in a per-widget `Map` keyed by `type + source`, so re-renders reuse finished output and do not flicker. Choices become interactive only once the stream ends.

## 4. Configuration

Widget option:

```ts
rich?: { tables?: boolean; charts?: boolean; choices?: boolean; diagrams?: boolean; math?: boolean; svg?: boolean; images?: boolean;
         mermaidUrl?: string; katexUrl?: string }
```

All features default to `true`. URLs default to pinned jsdelivr builds (`mermaid@11.4.1`, `katex@0.16.11`); hosts with strict CSP self-host and override them. A disabled feature renders its block as plain code.

Core: `capabilities.richResponses?: { enabled: boolean }`, default enabled. When enabled, `buildMessages` appends a fixed ~250-token format guide to the static system prompt (counted in the token budget) describing tables, the `chart` and `choices` JSON shapes, `mermaid`, `svg`, and math syntax, with guidance to use them only when they help. `WidgetConfig.capabilities.richResponses: boolean` is exposed; the widget still renders whatever Markdown arrives, but the server flag controls whether the model is told about the formats.

## 5. Error handling

Every block renders in its own `try`. Failure, invalid input, or a lazy-load failure (offline, CSP) renders the raw source as a code block with a small muted note; the rest of the reply is unaffected. Lazy-load failures are cached per URL so a blocked CDN is not retried on every delta.

## 6. Testing

New `tests/rich-rendering.test.mjs` (jsdom, same harness as `widget-regressions`) and `tests/rich-prompt.test.mjs` (core):

- table with alignment and inline Markdown in cells
- chart JSON produces an `svg` with the expected mark count and a hidden data table; invalid JSON falls back to code
- choices: click sends the message; earlier groups disable after next send; multi-select sends joined labels; History-loaded choices disabled
- SVG block appears only as `img[src^="data:image/svg+xml"]`; no `<svg>`/`<script>` from model content in the shadow DOM
- image URL scheme allowlist (`javascript:` rejected)
- mermaid/math use a stubbed loader; load failure falls back to code
- unclosed fenced chart block mid-stream shows placeholder
- core: format guide present when enabled, absent when disabled

The Express example's mock mode gains a canned reply exercising every block type. `docs/customization.md` documents the `rich` option and block formats; a changeset is added.
